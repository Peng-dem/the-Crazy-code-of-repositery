# Price Recognizer（实付价格识别）

## 概述

从图片中提取商品的**实际支付价格**（用户最终实际支付的钱），而不是页面上的标价、划线价或划线后价格。核心难点：电商页面同时存在原价、折扣价、券后价、运费、合并付款等多个金额，必须准确定位"实付"字段。

## 工作流程

### 第 1 步：读取图片

用 Read 工具读取用户提供的图片路径（WorkBuddy 具备视觉能力，可直接查看图片内容）。如果用户给的是剪贴板描述或 URL，先获取到本地图片文件再读取。

### 第 2 步：判断图片类型

先观察图片整体，确定属于哪一类，不同类型的"实付价"定位策略不同：

| 图片类型 | 实付价所在位置 |
|---------|--------------|
| 支付成功页 / 支付宝·微信支付凭证 | 支付金额（大字，通常带"¥"） |
| 订单详情页（订单列表点进去的详情） | "实付款"字段（通常在订单状态栏或金额明细区） |
| 订单列表页 | 每个订单卡片上的金额（需确认是否含运费） |
| 商品详情页（未下单） | 没有"实付价"！只有预估到手价，须明确告知用户 |
| 聊天记录截图 | 转账金额或商家报价，需结合上下文判断 |
| 纸质小票 / 收据 | "合计""实收""应付金额" |
| 退款/售后页 | 注意区分"退款金额"与"支付金额" |

**关键判断**：如果图片是商品详情页（还没买），如实告诉用户图片中没有实付信息，只能给出当前售价/券后价，不要把促销价伪装成实付价。

### 第 3 步：提取全部价格字段

逐个列出图中出现的所有金额及其标签文字，包括：商品标价、划线价（原价）、优惠金额、运费、实付款、退款金额等。**禁止跳过这一步直接报一个数**——只有先列全，才能交叉校验。

### 第 4 步：按优先级确定实付价

按以下优先级锁定实付金额（命中即停）：

1. **明确标签**：带"实付款 / 实付 / 实际支付 / 已付款 / 合计支付 / 支付金额 / 实收"等字样的金额
2. **支付凭证大字金额**：支付宝/微信支付成功页中央的大号金额
3. **订单状态栏金额**：订单详情页顶部状态区显示的金额（如"待收货 ¥89.00"）
4. **推算校验**：若无明确实付字段，用「商品成交价 × 数量 + 运费 − 优惠」推算，并标注为推算值

**必须排除的干扰项**（这些不是实付价）：
- 划线价（带删除线的原价）
- "价格 ¥xx 起"中的"起"字价
- 拼团价/预售价等未支付的价格
- 单件价 vs 多件总价混淆（看清数量 × 单价）
- 退款页面的"可退金额"
- 积分、金币抵扣的虚拟数值

### 第 5 步：交叉校验

用两种方式校验后再输出：

- **算术校验**：商品金额 + 运费 − 优惠 ≈ 实付款（误差须为 0，否则说明识别有误，重新检查）
- **数量校验**：确认金额是单件价还是订单总价，核对商品数量字段
- 若图中字迹模糊、遮挡导致无法确认，如实标注"不确定"，说明哪一笔有歧义，请用户补充截图

### 第 6 步：结构化输出

按以下格式输出（表格或 JSON 均可，字段齐全即可）：

```
实际支付价格：¥89.00
├─ 商品金额：¥95.00
├─ 运费：¥0.00（包邮）
├─ 优惠：-¥6.00（店铺优惠券）
└─ 校验：95 + 0 − 6 = 89 ✅
图片类型：订单详情页（淘宝）
置信度：高（金额旁有"实付款"字样）
```

当用户只需要一个数字时，把"实际支付价格"放在最前面单独一行，明细放后面。批量图片（3 张以上）时用表格汇总，每行一张图。

## 资源

### references/price-fields-guide.md

各主流平台价格字段对照表和 UI 识别要点。当识别常见平台（淘宝/京东/拼多多/抖音/美团/支付宝/微信）截图时加载此文件辅助定位实付字段。

### scripts/parse_price.py

价格字符串确定性解析脚本。当需要把识别出的价格文本（如"¥1,299.00"、"1万2"、"89.9"）归一化为数值，或对多个金额做算术校验时执行：

```bash
python scripts/parse_price.py "¥1,299.00"        # → 1299.00
python scripts/parse_price.py --check 95.00 0.00 6.00 89.00   # 校验 95+0-6 是否等于 89
```

## 注意事项

- 金额识别以图片中的实际文字为准，禁止根据常识补全或"修正"金额
- 模糊不清的数字宁可信其不可辨，也不要猜（易混淆：3/8/9、1/7、5/6、0/8）
- 多商品合并订单：先报订单总实付，再分列每个商品的分摊金额（如有）
- 涉及退款/部分退款的图片，区分"原支付金额"和"实际到账/最终支出"，按用户问题回答对应口径
